# CLAUDE.md

AI 에이전트가 이 폴더에서 일할 때 매번 읽는 최상위 지침입니다.
이 파일은 목차입니다. 규칙의 본문은 각 정본 문서에 있고, 여기에는 이름과 한 줄 요약과 위치만 적습니다.

## 문서 지도

- 코드 규칙 정본: `RULES.md`. 새 코드를 만들거나 고치기 전에 읽는다.
- 교훈 원장: `LESSONS.md`. 사고가 나면 사건과 교훈을 한 건씩 쌓는다. 같은 사고가 두 번 나면 `RULES.md`로 올린다.
- 동작 변경 기록: `CHANGEBOOK.md`. 동작이 바뀌는 수정마다 한 줄. 자동수리 AI가 이걸 읽고, 사람이 고쳐 놓은 것을 되돌리지 않는다.
- 작업 선점판: `TASKBOARD.md`. 30분 넘는 작업은 시작 전에 한 줄 등록하고 끝나면 지운다. 같은 작업이 이미 있으면 손대지 않는다.
- 주제별 정본 맵: `docs/streams/stream_*.md`.

## 작업 스트림 라우팅

주제가 들어오면 코드를 뒤지기 전에 해당 맵부터 읽는다. 맵에는 현황, 파일 위치, 배포 절차, 함정, 최근 변경이 있다.

- 공용 모듈 → `stream_platform.md` (여기를 고치면 전부에 퍼진다)
- 업무 리서치 → `stream_research.md`
- 콘텐츠 발행 → `stream_publish.md`
- 감사·자동수리 → `stream_audit.md`

모든 코드는 스트림 하나에 반드시 배정된다. 점검: `python tools/stream_check.py streams.json` (미배정 0이 정상).
작업을 마치면 그 맵의 "최근 변경"에 날짜와 핵심 1~3문장을 남긴다. 안 남기면 다음 세션이 처음부터 다시 뒤진다.

## 규칙을 세울 때의 규칙

1. 내용은 정본 한 곳에만 쓴다. 라우팅 문서에는 이름·요약·위치만. 본문을 복사하면 정본을 고칠 때 사본이 낡는다.
2. 개수·날짜·목록은 라우팅 문서에 적지 않는다. 세야 하면 정본에서 센다.
3. 규칙을 풀거나 완화하면 제목부터 고친다. 본문 아래 정정만 덧붙이면 제목만 읽는 쪽은 여전히 옛 규칙대로 움직인다.
4. 논쟁 중인 수치는 규칙서에 두지 않는다.
5. 검사기 없는 규칙은 또 건너뛴다. 새 규칙은 기계로 잡을 수 있는지부터 보고, 안 되면 그 사실을 규칙에 적는다.

## 지침이 부딪힐 때

위가 이긴다.

1. 돈과 외부 발행의 안전
2. 정직한 실패 보고. 조회에 실패하면 옛값으로 조용히 메우지 않는다
3. 임무 완수
4. 효율

"에러를 없애라"의 답이 "에러를 숨겨라"가 되면 안 된다. 3을 위해 검증·승인·알림을 약하게 만드는 해법은 쓰지 않는다.

## 알아서 할 것과 물어볼 것

- 알아서 할 것은 방법이다. 로그인, 도구 선택, 조사, 읽기, 죽은 자원 대신 살아 있는 자원으로 넘어가기.
- 물어볼 것은 결정이다. 돈이 움직이는 변경, 밖으로 나가는 글, 되돌릴 수 없는 행위, 무인 반복 예약, 결론을 바꾸는 전제(기간·대상·범위).
- 판단 한 줄: 지금 내가 사람 대신 결정하고 있나, 시킨 일을 어떻게 할지 정하고 있나.
